Quick terminology note first: what you're calling "the kernel" here is really the command line / terminal (shell) — the kernel itself is the underlying OS core, not something you type commands into directly. Commands like lsblk, mount, eject are userspace tools that talk to the kernel, but you're not accessing "the kernel" itself in the way the phrasing suggests. I'll use "terminal" below for clarity, but the commands are exactly what you're asking for.

1. See what disks/devices are connected

bash
lsblk

This lists all block devices (drives, partitions, USB storage) in a tree view — you'll see your Kobo appear as something like sdb with a partition sdb1 once it's plugged in and mounted (or mountable).

For more detail (filesystem type, UUID, labels):

bash
lsblk -f

To specifically watch for the Kobo appearing/disappearing in real time as you plug/unplug it:

bash
watch -n 1 lsblk

Or check kernel messages the moment you plug it in:

bash
dmesg | tail -20

(run this right after plugging in the Kobo — it'll show the USB device being detected, assigned a /dev/sdX name, etc.)

2. Access the Kobo's contents

Kobo devices mount as a standard USB mass-storage/MTP device with a FAT32 filesystem. Once plugged in, Ubuntu usually auto-mounts it under /media/fahim/KOBOeReader or similar. Check where it landed:

bash
lsblk -f

Look for the MOUNTPOINT column next to the Kobo's partition entry. Then just cd into it:

bash
cd /media/fahim/KOBOeReader
ls

If it didn't auto-mount (rare, but possible depending on your desktop environment/hub), mount it manually:

bash
sudo mkdir -p /mnt/kobo
sudo mount /dev/sdb1 /mnt/kobo   # replace sdb1 with whatever lsblk showed

3. Eject the Kobo safely

If it auto-mounted via your desktop environment, the clean way is:

bash
udisksctl unmount -b /dev/sdb1
udisksctl power-off -b /dev/sdb

(unmount flushes and unmounts the filesystem; power-off tells the kernel to safely power down that USB device before you physically unplug it — this is the real "eject.")

If you mounted it manually instead:

bash
sudo umount /mnt/kobo

Important with your USB hub specifically: since you're going through a hub (and given the suspend/USB issues we diagnosed earlier on this same laptop), always run the eject/unmount commands before physically pulling the cable — pulling a mounted drive without unmounting first risks corrupting the Kobo's filesystem or its internal database of book metadata. Given your hub already showed up as a plausible factor in your earlier USB resume failures, it's worth being extra deliberate about the clean-unmount step here rather than just yanking the cable.
